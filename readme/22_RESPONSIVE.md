# 22 · الاستجابة — شاشةٌ واحدة على كل المقاسات

> **الأمر المختصر:** لا تقرأ `MediaQuery` بشاشة، ولا تحسب نسبةً من ارتفاعها.
> اقرأ `context.screen`، وضع محتوى الصفحة في `ResponsiveContentBox`.
>
> الكود: [`lib/ui/responsive/`](../lib/ui/responsive/) · القواعد اليومية:
> [`lib/CLAUDE.md`](../lib/CLAUDE.md) §Responsive.

## ١ · لماذا طبقةٌ بدل حسابٍ بكل ملف

كان بالمستودع مقياسان لنفس الشيء:

- `context.sw` و`context.sh` — نسبةٌ مئوية من مقاس الشاشة.
- أرقامٌ ثابتة من الفيغما (`SizedBox(height: 24)` · `width: 115`).

وكلاهما ينكسر، بطريقتَين متعاكستَين:

| | تنكسر حين | العطل الفعلي |
|---|---|---|
| **النسبة من الارتفاع** | يفتح الكيبورد، أو يستلقي الجهاز | `context.sh * 0.08` تُحسب من **الشاشة كاملةً** لا من الجسد المتبقّي. فتحُ الكيبورد على هاتفٍ بارتفاع ٦٦٧ كان يدفع زرَّ الدخول خارج الحدّ: `RenderFlex overflow` بالتصحيح، شريطٌ مخطَّط بالإصدار، وزرٌّ لا يُنقر |
| **الرقم الثابت** | يصغر الجهاز أو يكبر | علامةٌ بقطر ١١٥ تملأ ثلث هاتف ٣٢٠، وتضيع بأعلى لوحٍ ١٠٢٤. ونموذجٌ بلا حدّ عرض يصير على اللوح حقلاً تفصل لافتتَه عن قيمته ثلثُ شاشة |

**والطبقة تحلّ الاثنين بمصدرٍ واحد**: رقمُ الفيغما كما هو، محمولاً بمعاملٍ
واحدٍ محسوبٍ مرّةً فوق التطبيق كلّه.

## ٢ · أصناف الشاشة

الحدُّ من **عرض النافذة** لا من `shortestSide`: ما يقرّر عموداً أو عمودَين هو
العرض الذي بين يدي التخطيط الآن. وهاتفٌ مستلقٍ يملك عرض لوحٍ صغير ويستحقّ
تخطيطَه، وإن بقي هاتفاً.

| `ScreenClass` | العرض | الأجهزة | `gutter` | `formMaxWidth` | `contentMaxWidth` | أعمدة |
|---|---|---|---|---|---|---|
| `compact` | < ٣٦٠ | iPhone SE · شاشات ٣٢٠ | ١٦ | ∞ | ∞ | ١ |
| `medium` | ٣٦٠–٥٩٩ | أغلب الهواتف | ٢٠ | ∞ | ∞ | ٢ |
| `expanded` | ٦٠٠–٨٩٩ | لوحٌ ٧–٨″ · هاتفٌ مستلقٍ · مطويٌّ مفتوح | ٣٢ | ٤٨٠ | ٨٤٠ | ٣ |
| `large` | ≥ ٩٠٠ | لوحٌ ١٠″ فأكبر | ٤٨ | ٤٨٠ | ٨٤٠ | ٤ |

و`isTablet` منفصلٌ عنها: `shortestSide >= 600` — معيار أندرويد نفسه
(`sw600dp`). **أقصرُ ضلعٍ لا العرض، لأن الجهاز لا يصير هاتفاً بتدويره.**

### معامل التكبير `scale`

الأساس **٣٩٠** — عرض الهاتف الذي رُسمت عليه تصاميم الفيغما.

```
هاتف : clamp(shortestSide / 390, 0.85, 1.05)
لوح   : 1.15  ثابتاً
```

⚠️ **واللوح لا يأخذ التناسب الحرّ عمداً.** `width / 390` يعطي اللوحَ ٢٫١،
فيصير الزرُّ بارتفاع ١١٠ بكسل والأيقونةُ بحجم راحة اليد: **تكبيرُ هاتفٍ لا
تخطيطُ لوح**. اللوح يكسب مساحته بالهوامش وبحدّ العرض، لا بتضخيم كل عنصر.

## ٣ · الاستعمال

```dart
import 'package:app_template/ui/responsive/responsive.dart';

final s = context.screen;

s.space(24)      // مسافةٌ من التصميم → ٢٤ عند ٣٩٠ · ٢١ عند ٣٢٠ · ٢٨ على لوح
s.size(115)      // مقاسٌ من التصميم (قطر · ارتفاع · أيقونة) — بلا تقريب
s.gutter         // هامش الصفحة الأفقي
s.gridColumns    // أعمدة الشبكة
s.isTablet · s.isCompact · s.isLandscape · s.screenClass

s.pick(compact: 1, expanded: 2, large: 3)   // قيمةٌ لكل صنف، وتسقط للأصغر
```

وبالودجات:

```dart
ResponsiveGap(24)                    // فراغٌ رأسيّ بمقاس التصميم، محمولاً

ResponsiveContentBox(                // حدُّ العرض + هامش الصفحة + توسيط
  width: ContentWidth.content,       // form (٤٨٠) · content (٨٤٠) · full (∞)
  child: ListView(...),
)

ResponsiveBuilder(                   // حين يختلف **التركيب** لا الرقم
  builder: (context, screen) =>
      screen.isTablet ? const _TwoPane() : const _OnePane(),
)
```

**و`pick` أوضح من `ResponsiveBuilder` حين يتغيّر رقمٌ فحسب** — الباني يبني
شجرتَين لفرقٍ عدديّ.

## ٣‑ب · شاشةٌ جديدة أو ودجةٌ جديدة — ماذا تكتب بالضبط

### جدول القرار — رقمٌ رقماً

**ابدأ من نوع الرقم، لا من نوع الملف.**

| الرقم الذي بيدك | اكتب | لا تكتب |
|---|---|---|
| فراغٌ رأسيّ بين عنصرَين | `ResponsiveGap(24)` | `SizedBox(height: 24)` · `24.heightBox` |
| فراغٌ أفقيّ داخل صفّ | `SizedBox(width: s.space(8))` | `8.widthBox` |
| هامشُ الصفحة الأفقي | `s.gutter` | `16` · `EdgeInsets.all(16)` |
| حشوةٌ داخل بطاقة أو حقل | `EdgeInsets.all(s.space(16))` | `16.allPadding` |
| قطرُ دائرة · ارتفاعُ زرّ · مقاسُ أيقونة | `s.size(115)` | `115` |
| ارتفاعٌ لا يجوز أن يصغر (مساحة لمس) | `math.max(48, s.size(52))` | `52` |
| مقاسُ خطّ | `context.textTheme.bodyMedium` | `s.size(14)` — **الخطّ يمرّ بالسلّم لا بهذه الطبقة** |
| عددُ أعمدةٍ · تركيبٌ يتبدّل | `s.pick(compact: 1, expanded: 2)` | `if (width > 600)` |
| نسبةٌ من الشاشة لورقةٍ سفلية | `context.sh * 0.85` ✅ **مسموح** | — قياسُ شاشةٍ حقيقيّ |

> **والخطّ استثناءٌ مقصود.** المقاسات كلُّها بـ`TextTheme`، و`ResponsiveScope`
> يقيّد تكبير النظام فوقها. تمريرُ مقاس خطٍّ بـ`s.size(...)` يضرب معاملَين
> ببعضهما ويكسر تسهيلات الرؤية.

### قالبُ شاشةٍ جديدة

```dart
@RoutePage()
class XScreen extends StatelessWidget {
  const XScreen({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      backgroundColor: context.colors.bgPage,
      appBar: const XHeader(),               // ← خارج الصندوق: يمتدّ للحافة
      body: ResponsiveContentBox(
        // content للقوائم والقراءة (٨٤٠) · form للحقول (٤٨٠) · full بلا حدّ
        width: ContentWidth.content,
        // false متى كان الجسد يحمل حشوته الأفقية أصلاً — وهو الغالب
        horizontalPadding: false,
        child: const XBody(),
      ),
    );
  }
}
```

**والقاعدةُ في موضع الصندوق**: كلُّ ما يمتدّ إلى حافة الشاشة — شريطٌ ملوّن،
ترويسةٌ بخلفية، صورةٌ ملء العرض — يبقى **خارجه**. وما يُقرأ صفّاً صفّاً يدخله.

| نوع الشاشة | `width` |
|---|---|
| استمارةُ إدخال · تأكيدٌ · حالةٌ فارغة | `form` |
| قائمةٌ · تفاصيلُ تُقرأ · إعدادات | `content` |
| خريطة · معرضُ صور · كاميرا | `full` (أو لا صندوق) |

### قالبُ ودجةٍ جديدة

```dart
class XCard extends StatelessWidget {
  const XCard({super.key});

  @override
  Widget build(BuildContext context) {
    final s = context.screen;             // ← سطرٌ واحد بأعلى build
    return Container(
      padding: EdgeInsets.all(s.space(16)),
      child: Column(
        children: [
          Icon(Icons.info_outline, size: s.size(24)),
          const ResponsiveGap(8),
          Text('...', style: context.textTheme.bodyMedium),
        ],
      ),
    );
  }
}
```

**والودجةُ لا تلفّ نفسها بـ`ResponsiveContentBox`** — الحدُّ قرارُ الشاشة
المضيفة، لا قرارُ البطاقة. ودجةٌ تحدّ عرضها بنفسها تصير غير قابلة للتركيب:
عمودان جنباً إلى جنب يفترقان بفراغٍ لا سبب له.

### بطاقةُ المراجعة — خمسة أسطر

- [ ] لا رقمَ خامّ بالتخطيط: كلٌّ مرّ بـ`s.space` أو `s.size` أو `s.gutter`
- [ ] لا `context.sh *` ولا `context.sw *` كمسافة
- [ ] جسدُ الشاشة داخل `ResponsiveContentBox` بـ`width` مناسب
- [ ] ما يمتدّ للحافة (ترويسة · شريط · صورة) **خارج** الصندوق
- [ ] جُرِّبت على ثلاثة: هاتف ~٣٦٠ · لوحٌ عموديّ (٨٠٠) · لوحٌ أفقيّ (١٢٨٠)

> **والتجريب ليس زينة.** `assert` داخل `NavigationRail` أسقط الشريطَ الجانبي
> بشاشةٍ حمراء، و`dart analyze` نظيفٌ عليه، **ولا يظهر على هاتفٍ قطّ** — الفرعُ
> لا يُبنى دون ٨٤٠ بكسل. كلُّ ما تكتبه لعرضٍ لا تملكه بجهازك يمرّ من غير حارس.

## ٤ · النطاق المركزي — وما يفعله وحده

`ResponsiveScope` مركَّبٌ بـ`builder:` الخاص بـ`MaterialApp.router` في
[`lib/app.dart`](../lib/app.dart) — أي **فوق كل مسارٍ وحوارٍ وورقةٍ سفلية**.
وهذا موضعه الوحيد: نسخةٌ ثانية بشاشةٍ ما تعني مقياسَين بنفس التطبيق.

يفعل أمرَين:

1. **يحسب `ScreenMetrics` مرّةً** ويوزّعها بـ`InheritedWidget`. والحساب من
   `MediaQuery.sizeOf` لا `MediaQuery.of`: الثاني يعيد بناء التطبيق كلَّه مع
   كل ظهورٍ للكيبورد (`viewInsets`).

2. **يقيّد تكبير الخط بين ٠٫٩ و١٫٣.**

   > إعدادُ «حجم الخط» بالنظام يصل **٢٫٠** على أندرويد و**٣٫١** على iOS مع
   > تسهيلات الرؤية. وعند ١٫٨ ينكسر كلُّ شريطٍ فيه نصّ — وهو أشيعُ عطلٍ
   > يُبلَّغ عنه من الميدان **ولا يظهر أبداً على جهاز المطوّر**.
   >
   > ⛔ **ولا يُلغى التكبير بجعله ١٫٠**: ذلك يكسر تسهيلات الرؤية كاملةً لمن
   > يحتاجها. يبقى للمستخدم +٣٠٪ محسوسة، ويبقى التخطيط قائماً.

## ٤‑ب · الاتجاه — الهاتف عموديٌّ، واللوح بالاتجاهين

كان `main.dart` يقفل `portraitUp | portraitDown` **للجميع**. وأثرُه على اللوح
ليس أن التطبيق يبقى عمودياً:

> أندرويد **يحبس** النشاطَ المقفول داخل نافذةٍ بنسبة هاتف وسط الشاشة، ويملأ ما
> حولها بالأسود. فلوحٌ بعرض ٢٥٦٠ كان يعرض التطبيق بعرض ٩٤٠ بشريطَين أسودَين —
> **ولا يُصلحه أيُّ تخطيطٍ بالداخل**، لأن النافذة نفسها هي المقصوصة. (مقيسٌ على
> محاكي Pixel Tablet، 2026-08-30.)

| الجهاز | الاتجاه | لماذا |
|---|---|---|
| هاتف (`shortestSide < 600`) | عموديّ وحده | شاشةُ هاتفٍ مستلقية ارتفاعُها ~٣٦٠ بكسل، ومع كيبوردٍ مفتوح ~١٥٠: استمارةٌ بعدّة حقول لا تُملأ هناك بحال. **وهذا افتراضُ القالب لا قانون** — يبدَّل بموضعٍ واحد بـ`OrientationPolicy` |
| لوح (`≥ 600`) | الاثنان | الفتحُ للّوح وحده هو ما تفعله تطبيقات جوجل نفسها |

والقرار يقع **مرّتين**، وكلتاهما ضرورية — راجع `OrientationPolicy`:

1. `applyAtStartup()` بـ`main()` قبل أول إطار، فلا يظهر اللوح محبوساً ثم يتّسع.
2. `applyFor(...)` من `ResponsiveScope` بأول تخطيطٍ حقيقيّ، لأن `physicalSize`
   قد تكون **صفراً** قبل أول إطارٍ على بعض الأجهزة فتسقط البداية إلى «اقفل»
   احتياطاً.

## ٤‑ج · التنقّل — شريطٌ سفليّ دون ٨٤٠، وجانبيٌّ فوقها

> ⬜ **غيرُ مبنيٍّ بالقالب بعد.** `BrandNavBar` و`BrandNavRail` ينتظران، وقشرةُ
> التطبيق اليوم شريطٌ سفليٌّ واحد بكل المقاسات. وما دون **مواصفةٌ جاهزة** —
> الحدُّ وسببُه والمزالق الثلاثة — تُنفَّذ كما هي حين يُبنى الشريط الجانبي.


| العرض | الشريط | الأجهزة |
|---|---|---|
| < ٨٤٠ | `BrandNavBar` سفلياً — و`extendBody: true` | هاتف · **ولوحٌ عموديّ (٨٠٠)** |
| ≥ ٨٤٠ | `BrandNavRail` جانبياً — و`extendBody: false` | لوحٌ أفقيّ (١٢٨٠) |

### ولماذا ٨٤٠ لا ٦٠٠

كان الحدُّ ٦٠٠ — أي كلُّ لوحٍ بأي اتجاه — وهو ما تنصّ عليه Material 3 حرفياً
لصنف `Medium`. **وصُحّح (2026-08-30)** لأن الحرف هنا يخالف الغرض:

| الاتجاه | العرض | المحورُ الشحيح | ما يقتطعه الشريط من الشحيح |
|---|---|---|---|
| لوحٌ عموديّ | ٨٠٠ | **العرض** | الجانبيّ: ٨٠ من ٨٠٠ = **١٠٪** |
| لوحٌ أفقيّ | ١٢٨٠ | **الارتفاع** | السفليّ: ٦٦ من ٨٠٠ = **٨٪** |

كلُّ وضعٍ يريد الشريطَ على محوره **الوافر**: العموديُّ ارتفاعُه وافر فيأخذ
السفليّ، والأفقيُّ عرضُه وافر فيأخذ الجانبيّ. والحدُّ ٦٠٠ كان يعطي العموديَّ
عكسَ ما يحتاج.

وسببان أخصُّ بهذا التطبيق: ترويسات الشاشات **شرائطُ خضراء بعرضٍ كامل** يقطعها
الجانبيّ · وتطبيقٌ ميدانيّ يُمسك باليدين، فبالعموديّ الإبهامُ يبلغ الأسفل لا
الجانب.

و٨٤٠ ليس مخترعاً: هو حدُّ `Expanded` بأصناف نوافذ Material 3 — فاللوح العموديّ
دونه والأفقيّ فوقه، بلا حالةٍ بينهما.

**والتبويبات هي هي**: نفس `NavigationDestination`، ونفس `IndexedStack` — فلا
حالةَ تُفقد بتدوير الجهاز. والشريط الجانبي أوّلَ `Row`، فيقع على **يمين**
الشاشة بالعربية تلقائياً.

### ثلاثةُ مزالق بالشريط الجانبي — كلُّها صامتة على الهاتف

| المزلق | ما يحدث |
|---|---|
| `elevation: 0` | `assert(elevation == null || elevation > 0)` — **شاشةٌ حمراء وقت التشغيل**. والصفر هو ما يكتبه المرء تلقائياً ليقول «بلا ظلّ» |
| `indicatorColor` مع `useIndicator: false` | `assert(useIndicator \|\| indicatorColor == null)` — شاشةٌ حمراء كذلك |
| بلا `SafeArea` | أوّلُ تبويبٍ يقع **تحت شريط الحالة**: `Scaffold` يحقن حشوة النظام بـ`bottomNavigationBar` تلقائياً ولا يفعلها لودجةٍ داخل `body`، وقشرةُ التطبيق `Scaffold` **بلا `AppBar`** |

⚠️ **ولا يمسك `dart analyze` واحداً منها، ولا يظهر أيٌّ منها على هاتف قطّ** —
الشريط الجانبي لا يُبنى دون ٨٤٠ بكسل. الثلاثة أُمسكت بالتجريب على محاكي لوحٍ
لا بالمراجعة.

> **واللون يسكن `DecoratedBox` لا `NavigationRail`**: `SafeArea` تقتطع من
> الشريط نفسه، فلو حمل هو اللونَ لظهرت حشوةُ شريط الحالة **بلون الصفحة**
> شريطاً باهتاً فوق الأخضر.

## ٤‑د · الورقة السفلية

`AppBottomSheet` يحصر عرضه بـ**٦٤٠** ويوسّطه فوق ٦٠٠ بكسل — ما تنصّ عليه
Material 3 للورقة على الشاشات الكبيرة. وورقةٌ تعبر ١٢٨٠ بكسل ليست ورقةً بل
شريطٌ يقطع الشاشة: زرّاها يفترقان بعرض راحتَي يد، وعنوانُها الموسَّط يبعد عن
كليهما. والتوسيط تلقائيّ — `showModalBottomSheet` يوسّط أي ورقةٍ قيدُها أضيق من
الشاشة.

## ٥ · نمطُ الشاشة الطويلة — بدل النِّسَب

الشاشة التي تحمل نموذجاً قصيراً (دخول · تأكيد · حالة فارغة) تُبنى هكذا،
لا بفراغاتٍ نسبية:

```dart
LayoutBuilder(
  builder: (context, constraints) => SingleChildScrollView(
    reverse: true,                       // أسفلُ المحتوى يلتصق بالكيبورد
    padding: EdgeInsets.symmetric(vertical: screen.space(24)),
    child: ConstrainedBox(
      constraints: BoxConstraints(
        minHeight: math.max(0, constraints.maxHeight - screen.space(24) * 2),
      ),
      child: Column(
        mainAxisAlignment: MainAxisAlignment.center,
        children: [...],
      ),
    ),
  ),
)
```

- شاشةٌ طويلة ⇒ يتوسّط المحتوى بدل أن يُدفع لأعلاها بنسبةٍ عمياء.
- شاشةٌ قصيرة أو كيبوردٌ مفتوح ⇒ `maxHeight` يتقلّص، فيتجاوز المحتوى الحدَّ
  الأدنى ويصير المشهد قابلاً للتمرير **من تلقائه**.

⬜ **ولا مثالَ منفَّذاً بالقالب بعد** — أوّلُ شاشةٍ تُنقل هي أوّلُ تطبيقٍ له.

## ٦ · حالةُ القالب اليوم — ما هو موصولٌ وما ينتظر

| الموضع | الحالة |
|---|---|
| `ResponsiveScope` بـ`app.dart` | ✅ موصول — كل شاشةٍ تحته |
| تقييد تكبير الخط (٠٫٩–١٫٣) | ✅ يعمل على كل الشاشات بلا استثناء |
| سياسة الاتجاه (`OrientationPolicy`) | ✅ موصولة — `main()` + تصحيحٌ بـ`ResponsiveScope` |
| `AppBottomSheet` — عرضٌ محدود موسَّط (٦٤٠) | ✅ مركزيّ: كل ورقةٍ بالتطبيق تكسبه بلا تعديل |
| **شاشات القالب** (`auth/` · `home/` · `settings/` · `splash/`) | ⬜ **لم تُنقل بعد** — ما زالت بأرقامٍ ثابتة و`context.sw`/`context.sh`. تُنقل شاشةً شاشةً، والصفُّ يُملأ هنا مع كل نقلة |
| `BrandNavRail` — الشريط الجانبي فوق ٨٤٠ | ⬜ **غير مبنيّ** — راجع §٤‑ج |

> ⚠️ **والطبقة موصولة والشاشات لم تُنقل** — وهذا مقصود: `ResponsiveScope`
> و`OrientationPolicy` **لا تكسران شيئاً قائماً**، فتُركَّبان أولاً ثم تُنقل
> الشاشات تباعاً. وأثرُهما على الهاتف قبل النقل **معدومٌ حرفياً** عدا تقييد
> تكبير الخط — وهو إصلاحٌ لا تغيير.

⚠️ **ولا يُلَفّ جسدُ شاشة القشرة كلُّه بـ`ResponsiveContentBox`.** كلُّ
تبويبٍ `Scaffold` كاملٌ بخلفيته وشريطه، فحدُّ العرض هناك يضع شريطَين فارغَين
حول **الشاشة كلها** بما فيها الترويسة. الحدُّ يوضع **داخل** جسد كلّ شاشة، تحت
ترويستها.

> **و`horizontalPadding: false` بكلّ نقلةٍ لجسدٍ يحمل حشوته الأفقية أصلاً** —
> وإلا تضاعفت. والمنقول هو **حدُّ العرض والتوسيط وحدهما**، أي أن الأثر على
> الهاتف **معدومٌ حرفياً**: `maxWidth` بلا حدّ دون ٦٠٠ بكسل، والحشوة صفر.

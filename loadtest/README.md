# Load Testing — k6

> **يُحدَّث هذا الملف عند إضافة/تعديل أي سيناريو k6** — مُسجَّل بجدول
> «Mandatory Documentation Sync» بـ`CLAUDE.md` الجذري، فأي تعديل بدون تحديث
> هذا الملف يُعتبر انحرافاً.

سكربتات k6 لاختبار **الضغط على backend_template** — كم مستخدم/جهاز متزامن
يتحمّل السيرفر، لا سلوك التطبيق نفسه. لاختبار بيانات كبيرة/offline/مزامنة
على الجهاز راجع [`lib/modules/sync/LOAD_TEST_PLAN.md`](../lib/modules/sync/LOAD_TEST_PLAN.md)
بدلاً من هنا — أداة مختلفة تماماً لسؤال مختلف تماماً.

منفصل عمداً عن `scripts/` (تلك Dart تُشغَّل بـ`dart run`؛ هذه JS تُشغَّل
بـ`k6 run` مباشرة — لا علاقة لها بـ`gen_code.dart` أو `check_structure.dart`).

---

## التشغيل

```bash
k6 run --env BASE_URL=http://localhost:3000/api/v1 loadtest/k6/account_cycle.js
```

`BASE_URL` **يجب أن يتضمّن `/api/v1`** — نفس القيمة التي يقرأها التطبيق من
`.env.{flavor}.json` (`Env.baseUrl`، راجع `readme/40_SCRIPTS.md` §3.1). كرّر
التشغيل بنفس السكربت مع رابط كل مرحلة (dev/staging/prod) حين تتوفر.

⛔ **لا تُشغِّل مباشرة على production** — staging أو بيئة معزولة فقط.

---

## متى تُضاف سيناريو جديد

**ليس كل feature/endpoint يحتاج k6.** السكربت يبقى يدوياً بقصد — لا تشغيلٌ
تلقائي عند `scaffold_feature.dart` (نفس منطق عدم توليد الاختبارات، راجع
`readme/40_SCRIPTS.md` §8‑هـ). أضف سيناريو حين ينطبق **أي** من:

| المعيار | مثال |
|---|---|
| يُستدعى من عدة مستخدمين بنفس اللحظة واقعياً | تسجيل دخول، قائمة رئيسية بعد فتح التطبيق |
| كتابة/تعديل بيانات مشتركة، لا قراءة فردية بسيطة | إنشاء سجل، رفع مرفق |
| نقطة حرجة يُكلف فشلها تحت ضغط | auth، دفع، أي مسار يحجب باقي التطبيق عند تعطّله |

إعدادات بسيطة (تغيير لغة، تفضيل محلي) لا تستاهل سيناريو.

## كيف تُضاف

1. ملف جديد `loadtest/k6/<feature>.js` — انسخ بنية `account_cycle.js`
   (`setup()` يجهّز بيانات/جلسات مرة وحدة، `default()` هو الدورة لكل VU).
2. راعِ أي rate limit بالباك (`backend_template/src/core/middleware/`) قبل
   كتابة `setup()` — `register` مثلاً محدود ٥/ساعة لكل IP، فاختبار حمل من
   جهاز واحد يصطدم به بسرعة إن أُهمل. سجّل مستخدمين تجريبيين مرة وأعد
   استخدامهم بدل تسجيلٍ لكل VU.
3. أضف سطر جدول بهذا الملف (تحت «السيناريوهات الموجودة») يذكر: الملف،
   الـendpoint(s)، وتاريخ الإضافة.
4. حدّث هذا الملف بنفس الـcommit — لا لاحقاً.

## قيود معروفة

- **`POST /account/register` محدود ٥ طلبات/ساعة لكل IP** (`registerRateLimit`).
  `account_cycle.js` يتجاوزها بتسجيل مستخدمين مرة وحدة بـ`setup()` وإعادة
  استخدامهم — لا تُسجّل مستخدماً جديداً لكل VU أو لكل iteration.
- **`POST /account/login` محدود ٥ محاولات/١٥ دقيقة لكل بريد ولكل IP**
  (`loginRateLimit`)، لكن **يُصفَّر عند نجاح الدخول** — فتكرار دخولٍ ناجح لا
  يصطدم به.
- لاختبار حملٍ يتجاوز الـ٥ حسابات (تسجيل فعلي بحجم كبير، لا إعادة استخدام)،
  ابنِ المستخدمين مباشرة بقاعدة البيانات (نمط `backend_template/scripts/
  seed_sync_load.ts` بـ`lib/modules/sync/LOAD_TEST_PLAN.md` §٤) بدل المرور
  بـ`/account/register` — أو ارفع الحدّ مؤقتاً بالباك لبيئة الاختبار فقط.

# تصميم موديول المزامنة — الطبقات والجداول ودورات الحياة

> **الحالة:** تصميمٌ مقترح للمراحل P3–P4.5 · **المبنيّ اليوم:** الجداول الأربعة الأولى فقط
> **الخطة والحالة:** [`PLAN.md`](PLAN.md) · **خطوات التركيب:** [`SETUP.md`](SETUP.md)
>
> **اقرأ هذا قبل كتابة أي كود لـP3 وما بعدها.** كل قرار هنا مربوطٌ بالعطل الذي يمنعه؛
> قرارٌ بلا عطلٍ يبرّره هو قرارٌ سيُنقض عند أول ضغط.

## ١. المبدأ الحاكم

> **الشاشة لا تعرف أن هناك شبكة.**

```
┌────────────── UI ──────────────┐
│  Cubit ← Stream<T> ← Repository ← LocalStore.watch()
└────────────────────────────────┘
                 ▲ المصدر الوحيد للقراءة
┌──────── SQLite: app_sync.db ────────┐   ┌──── نظام الملفات ────┐
│ synced_entities · sync_queue        │   │ <appDocs>/sync/      │
│ sync_meta · sync_operations_log     │◄─►│   files/<sha[0:2]>/  │
│ ＋ bundles · bundle_items           │   │   tmp/<id>.part      │
│ ＋ attachments · download_queue     │   └──────────────────────┘
│ ＋ manifest_snapshots               │
└─────────────────────────────────────┘
                 ▲
        SyncEngine: دفع → سحب → دمج → ملفات
                 ▲
        SyncGate: سبعة شروط قبل أي دورة
```

الـrepository يقرأ من القاعدة ويعيد `Stream`؛ والمزامنة عمليةٌ خلفية تكتب في نفس
القاعدة فتتحدث الشاشة من تلقائها. هذا يجعل «دون اتصال» **الحالة الافتراضية** لا
حالةً استثنائية — وهو الفرق بين تطبيق يعمل بلا إنترنت وتطبيق يتحمّل غيابه.

---

## ٢. ترتيب الدورة — وليس تفضيلاً

```
① دفع الطابور   ②
 سحب الدلتا   ③ دمج   ④ ملفات (تنزيل ثم رفع)
```

**الدفع أولاً.** لو سُحب قبله لوصلت نسخة السيرفر ودهست تعديلاً محلياً لم يُرسَل
بعد — فتضيع كتابة المستخدم **قبل أن تغادر جهازه**، وهي أسوأ صور الفقد لأن لا أثر
لها في أي مكان.

**الملفات أخيراً.** أثقل مرحلة وأطولها، ووضعها قبل الصفوف يعني أن انقطاعاً في
منتصف تنزيل 300MB يمنع وصول تعديلٍ نصّي حجمه بايتات.

## ٣. `SyncGate` — سبعة شروط بدل واحد

`_canSyncNow()` اليوم يفحص: الوضع · التفعيل · `isOnline` · wifiOnly.

| الشرط | ما يمنعه غيابه |
|---|---|
| اتصال فعلي (لا «واي‑فاي متصل») | بوابةٌ مقيَّدة تعطي واي‑فاي بلا إنترنت — والمزامنة تدور فتفشل فتتراجع أسّياً بلا سبب |
| توكن صالح | دورةٌ كاملة تنتهي بـ401 على كل وظيفة، فترتفع `retry_count` وتقترب من `failed` بسبب انتهاء جلسة لا بسبب خطأ |
| السيرفر حيّ (جسّ خفيف) | صيانةٌ بالخادم تستنزف عدّاد المحاولات لكل الطابور دفعةً واحدة |
| قفل غير مأخوذ | مزامنتان تكتبان نفس الصفوف |
| **مساحة كافية** | تنزيلٌ يبدأ فيملأ القرص فيفشل التطبيق كلّه، لا التنزيل وحده |
| بطارية فوق الحدّ | جولةٌ ميدانية تنتهي بجهازٍ ميت — وهو أسوأ من مزامنةٍ متأخرة |
| **عملٌ معلّق أصلاً** | دورةٌ كاملة كل خمس دقائق بلا شيء لتفعله |

## ٤. مخطَّط القاعدة — v3 القائم و v4 المقترح

### القائم (لا يُمسّ)

`synced_entities` · `sync_queue` · `sync_meta` · `sync_operations_log`

> **`sync_meta` مبنيّ بصفر مستهلك.** يستقبل بـP3 مؤشرات السحب، **واحداً لكل كيان**:
> `('cursor:notes', '{"updated_since":"…","after_id":"…"}')`. وهذا يفعل ثلاثة معاً:
> يعطي الجدول مستهلكه الأول · يُخرج مفتاح المؤشر من `core/platform/storage/persistence_keys.dart`
> حيث لا يجوز لموديول أن يكتب · **ويمنع فشلَ سحبِ كيانٍ من تقديم مؤشر غيره**
> فيبتلع تغييراتهم بصمت.

### المقترح — v4

```sql
-- وحدة العمل. الاسم عامّ عمداً: المشروع يسمّيها Assignment أو Route أو Survey.
bundles(
  bundle_id TEXT PRIMARY KEY,
  remote_id TEXT, title TEXT,
  state TEXT NOT NULL,          -- created|manifested|downloading|ready|inProgress
                                -- |uploading|synced|archived
  manifest_etag TEXT, manifest_fetched_at INTEGER,
  total_bytes INTEGER, downloaded_bytes INTEGER,
  total_files INTEGER, downloaded_files INTEGER, failed_files INTEGER,
  expires_at INTEGER, created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);

-- عضويةٌ لا نسخة: كيانٌ يظهر في حزمتين له صفٌّ واحد بـsynced_entities وصفّا عضوية.
bundle_items(
  bundle_id TEXT NOT NULL, entity_name TEXT NOT NULL, local_id TEXT NOT NULL,
  PRIMARY KEY (bundle_id, entity_name, local_id)
);

attachments(
  attachment_id TEXT PRIMARY KEY,
  bundle_id TEXT, entity_name TEXT, entity_local_id TEXT,
  role TEXT,                    -- photo|document|reference|signature
  remote_url TEXT, local_path TEXT,
  file_name TEXT, mime_type TEXT, size_bytes INTEGER,
  checksum TEXT, checksum_algo TEXT,
  bytes_received INTEGER NOT NULL DEFAULT 0,
  download_status TEXT NOT NULL, upload_status TEXT NOT NULL,
  origin TEXT NOT NULL,         -- server|device
  is_required INTEGER NOT NULL DEFAULT 0,
  last_accessed_at INTEGER,     -- LRU للإخلاء
  retry_count INTEGER NOT NULL DEFAULT 0, last_error TEXT,
  created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
);

download_queue(
  job_id TEXT PRIMARY KEY, attachment_id TEXT NOT NULL,
  priority INTEGER NOT NULL, next_retry_at INTEGER NOT NULL,
  retry_count INTEGER NOT NULL DEFAULT 0, status TEXT NOT NULL, last_error TEXT
);

manifest_snapshots(bundle_id TEXT PRIMARY KEY, etag TEXT, json TEXT, fetched_at INTEGER);
```

### أربعة قرارات في `attachments` تستحق التبرير

| القرار | العطل الذي يمنعه |
|---|---|
| **`download_status` و`upload_status` عمودان لا واحد** | صورةُ الجهاز لها رفعٌ بلا تنزيل، والمرجع عكسها. دمجهما يضع الحالتين على محورٍ واحد فيصير سؤال «هل الملف موجود محلياً؟» غير قابل للإجابة بلا معرفة أصله |
| **`origin` إلزامي** | ملفٌ من السيرفر ضاع ⇒ أعِد تنزيله. ملفٌ من الجهاز ضاع قبل رفعه ⇒ **فُقد إلى الأبد** ويجب أن يصرخ التطبيق. بلا العمود العطلان **متطابقان في الكود** |
| **`checksum_algo` بجانب `checksum`** | ترقية الخوارزمية بعد سنتين تجعل كل قيمة مخزّنة غير قابلة للتفسير، ولا سبيل للتمييز بين «مختلف» و«محسوب بطريقة أخرى» |
| **`(entity_name, entity_local_id)` لا `entityType/entityId` حرّتين** | مطابقةٌ لمفتاح `synced_entities` القائم. اصطلاحان للإشارة إلى نفس الصفّ ينحرفان |

## ٥. تخطيط الملفات

```
<appDocuments>/sync/
├── files/<sha256[0:2]>/<sha256>      ← المحتوى، مسمّى بمحتواه
└── tmp/<attachmentId>.part           ← الجزئي، ولا شيء يقرأ منه
```

| القرار | السبب |
|---|---|
| **نظام الملفات لا BLOB** | `PRAGMA integrity_check` يمسح الملف كاملاً عند الإقلاع · SQLite يقرأ الـBLOB صفّاً كاملاً · الكتابة تضخّم WAL بمقدارها · لا استئناف داخل صفّ · `DELETE` لا يحرّر مساحة بلا `VACUUM`، و`VACUUM` على 5GB يطلب 5GB إضافية مؤقتاً |
| **التسمية بالـchecksum** | إزالة تكرار مجانية: نفس الصورة المرجعية في ٥٠ موقعاً = ملف واحد على القرص |
| **`getApplicationDocumentsDirectory()`** | النظام يمسح `getTemporaryDirectory()` متى ضاقت المساحة — وهو ما يقع بالضبط في الجولات الطويلة كثيفة الصور |
| **`.part` وإعادة تسمية ذرّية** | ملفٌ ناقص باسمه النهائي = تطبيق يعرض PDF مقطوعاً ويظنّه سليماً |
| **البثّ إلى القرص** | `TransferFileDownloader` يحمّل الملف كاملاً في `List<int>` — مقبول لـCSV، قاتل لجولة |

## ٦. الـManifest

```jsonc
GET /bundles/:id/manifest        // ETag
{
  "bundle":   { "id": "…", "title": "…", "version": 12, "expires_at": "…" },
  "entities": [ { "entity_name": "notes", "id": "…", "version": 3, "updated_at": "…" } ],
  "files":    [ { "attachment_id": "…", "entity_name": "notes", "entity_id": "…",
                  "role": "photo", "url": "…", "size": 184320,
                  "checksum": "…", "checksum_algo": "sha256",
                  "required": true } ],
  "totals":   { "entities": 4820, "files": 1310, "bytes": 4187593216 }
}
```

**`totals` قبل أي بايت** — سطرٌ واحد بالسيرفر يمنع الفشل عند ٨٠٪، وهو أرخص بند
في التصميم كله وأكثرها إيلاماً عند غيابه.

**والـmanifest امتداد `/delta` إلى الملفات، لا آليةٌ ثانية:** نفس مبدأ «قل لي ما
تغيّر»، مطبَّقاً على محتوى لا يُنقل بالـJSON.

| الحالة محلياً | الحكم |
|---|---|
| غير موجود | نزِّل |
| موجود و checksum مطابق | **لا شيء** |
| موجود ومختلف | نزِّل بديلاً وبدّله ذرّياً |
| موجود وغائبٌ عن الـmanifest | أرشِف — **ولا تحذف** إن كان `origin=device` غير مرفوع |

## ٧. دورة حياة الحزمة

```
created → manifested → downloading ⇄ paused → ready
    → inProgress → uploading ⇄ retrying → synced → archived → purged
```

**بوابتان لا تُتجاوزان:**

1. **`ready` لا تُعلن** إلا بعد وصول كل كيان · تحقّق كل ملف `is_required=1` من الـchecksum · والمساحة فوق الاحتياطي. جامعٌ يكتشف في الميدان أن المراجع ناقصة **لا يملك حلاً** — لا شبكة ولا رجوع.
2. **`synced` لا تُعلن** إلا بخلوّ الطابور من كل عمليات هذه الحزمة **ومنها الملفات**. «رُفعت البيانات ولم تُرفع الصور» ليست `synced` بأي معنى مفيد.

**و`purged` لا تُبلَغ آلياً أبداً** ما دام هناك `origin=device` غير مرفوع. الحذف
التلقائي هنا فقدُ بيانات لا تنظيف.

## ٨. دورة حياة الملف

```
تنزيل:  pending → downloading(Range) → tmp/*.part → تحقق checksum
                → rename ذرّي → verified
                ↘ عدم تطابق → احذف .part → أعد → بعد N: failed

رفع:    captured(device) → نسخٌ فوري إلى مجلد التطبيق → queued
                → uploading → uploaded(مؤكَّد من السيرفر) → freed(بالسياسة)
```

**نسخ صورة الكاميرا لحظة الالتقاط، قبل إنشاء وظيفة الطابور.** `image_picker` يعيد
مساراً في المؤقت والنظام يمسحه متى ضاقت المساحة — وهو ما يقع في الجولات الطويلة
كثيفة الصور تحديداً. العطل: صفٌّ بالطابور يشير إلى ملف غير موجود، وصورةٌ قد تكون
الوحيدة لموقعٍ لن يُزار ثانية.

**ولا تُحذف صورة الجهاز إلا بعد تأكيد الرفع من السيرفر** — لا بعد إرسالها.

## ٨-ب. الوصول إلى ملف — المسار الكسول

```
الملف موجود محلياً؟
    نعم           → اعرضه · وحدِّث last_accessed_at
    لا + إنترنت   → نزّله → تحقّق من checksum → خزّنه → اعرضه
    لا + offline  → unavailableOffline  ← حالة عرضٍ أولى، لا رسالة خطأ
```

**والحالة الثالثة ليست فشلاً.** ملفٌ اختياري أُخلي بالأمس لتوفير مساحة، وجهازٌ
خارج التغطية اليوم — هذا نظامٌ يعمل كما صُمِّم. عرضُه شاشةَ خطأ يعلّم المستخدم
أن التطبيق معطوب، فيتوقف عن الإبلاغ عن الأعطال الحقيقية.

## ٨-ج. التقسيم الطبقي — ما يُنزَّل مسبقاً وما يُجلب عند الطلب

| النوع | الاستراتيجية | لماذا |
|---|---|---|
| بيانات منظَّمة | **شاملٌ دائماً** | ميغابايتات، وبلا اكتمالها لا توجد جولة |
| ملفات `is_required` | **شاملٌ قبل `ready`** | من يكتشفها ناقصةً في الميدان لا يملك حلاً |
| ملفات اختيارية | **عند الطلب + إخلاء** | جيجابايتات لا تسعها الأقراص |

`is_required` هو **حامل هذا التصميم**: بدونه إمّا تُنزَّل الجيجابايتات كلها فيمتلئ
القرص، أو يُترك كل شيء للطلب فيقف الجامع أمام نموذجٍ لا يستطيع فتحه.

## ٨-د. Cache Manager — والملف المُخلى ليس ملفاً محذوفاً

| القاعدة | ولماذا |
|---|---|
| الإخلاء **يفرّغ `local_path`** ويعيد `download_status` إلى `pending` | الصفّ هو ما يعرف كيف يُعاد التنزيل. حذفه يجعل الملف مفقوداً لا مُخلى |
| LRU على `last_accessed_at` | ما لم يُفتح منذ شهر أرخص ما يُستغنى عنه |
| **إخلاء استباقي** قبل الامتلاء | الإخلاء بعد فشل تنزيل إصلاحٌ متأخر بخطوة كاملة |

**والمحرَّمات الثلاثة — لا تُخلى أبداً:**

1. **`origin=device` غير مرفوع.** لا شيء في الكون يعيدها.
2. **ملفات حزمة `ready` أو `inProgress`.** الجامع في الميدان · المساحة تضيق ·
   المُخلّي يحذف PDF المرجعي للموقع القادم · لا شبكة لإعادته. **بدون هذا التجميد
   يتحوّل Cache Manager من حلٍّ إلى سببِ العطل الذي وُجد ليمنعه.**
3. **`is_required` لحزمة لم تنتهِ.** نفس السبب، قبل أن تبدأ الجولة.

## ٩. `origin` ليس حقلاً — بل محورُ ترتيبٍ للنظام كلّه

> **البيانات القادمة من السيرفر قابلة لإعادة التنزيل. صورةُ الجهاز غير المرفوعة
> لا بديل لها في الكون.**

| القرار | كيف يُشتقّ من `origin` |
|---|---|
| أولوية الرفع | ملفات الجهاز أولاً دائماً |
| سياسة الحذف والتنظيف | لا مساس بغير المرفوع، مهما ضاقت المساحة |
| ما يمنع الخروج والمسح | وجود `origin=device` غير مرفوع |
| التحذيرات | «ضاع ملف» مقابل «سأعيد تنزيله» — رسالتان مختلفتان لحدثين يبدوان واحداً |

## ١٠. التعارض

| البيانات | الاستراتيجية | السبب |
|---|---|---|
| مرجعية/إدارية | `serverWins` | الجهاز لا سلطة له عليها |
| نماذج جمعها هذا المستخدم | **دمج حقلي ثم `manual` عند التصادم الحقيقي** | جامعٌ ملأ ١٢ حقلاً لا يجوز أن يخسرها لأن الأدمن غيّر حقلاً آخر |
| حالة زمنية (زار/لم يزر) | `lastWriteWins` | حدثٌ زمني بطبيعته |
| **حذف مقابل تعديل** | **`manual` دائماً، بلا استثناء** | أدمن حذف موقعاً وجامع ملأ نماذجه: `serverWins` تمحو عمل ساعة، و`clientWins` تُحيي محذوفاً بقرار إداري. **لا قاعدة آلية تصيب هنا** |

**`clientWins` تُحذف** (P0.6): توثيقها يشترط ترويسة `X-Force-Override` غير موجودة
بالسيرفر، فمسارها الفعلي 409 → إعادة → 409 → `failed`. استراتيجيةٌ اسمها «العميل
يفوز» تنتهي بخسارة العميل بعد خمس محاولات.

**والتعارض حالةٌ محلية دائمة بواجهة، لا حدثٌ عابر.** `SyncStatus.conflicted` موجودة
أصلاً. جامعٌ في الميدان لا يستطيع حلّ ٤٠ تعارضاً وقت وقوعها؛ يحلّها آخر اليوم من
قائمة.

## ١١. الجلسة دون اتصال

| الحدث | اليوم | بالتصميم |
|---|---|---|
| فشل التجديد **بسبب الشبكة** | `sessionExpired` ⇒ خروج ⇒ مسح الهوية والصلاحيات | `offlineSession` ⇒ الهوية باقية · الصلاحيات المُستعادة باقية · لا خروج |
| **رفضٌ صريح** من السيرفر | خروج | خروج — بلا تغيير |
| خروج صريح والطابور غير فارغ | يمسح | **يُرفض ويحذّر** حتى يُرفع أو يُلغى صراحةً |
| تبديل حساب على نفس الجهاز | لا سياسة | **مسحٌ كامل** لقاعدة المزامنة وملفاتها — لا تصفية |

**المسح عند تبديل الحساب إلزامي أمنياً** (تسرّب بيانات بين حسابين على جهاز واحد =
عطل قاطع)، **ولا يجوز أن يقع نتيجة انتهاء توكن**. التمييز بين الحدثين هو كل
المرحلة P0.6.

## ١٣. تشخيصٌ داخليّ — استعلامات القاعدة

> **نُقلت من [`SETUP.md`](SETUP.md)، وموضعها هنا هو المقصود.** أسماء الجداول
> والأعمدة تفصيلُ تنفيذ، والباريل `sync_plugin.dart` لا يصدّر منها شيئاً عمداً.
> كودُ مستهلكٍ بُني على `sync_queue` أو `synced_entities` يكسر بأول هجرة —
> واستعمالها هنا **فحصٌ يدويّ أثناء التطوير** لا واجهةُ برمجة.
>
> المستهلك يسأل عن حالة المزامنة عبر السطح العام:
> `SyncQueueRepository.countPendingJobs()` · `SyncEntityStore.watch(entity)` ·
> `SyncController.triggerManualSync()`.

### كل ما فشل نهائياً

```sql
SELECT local_id, entity_name, last_error, updated_at
FROM synced_entities
WHERE sync_status = 'failed';
```

### كل ما ينتظر قراراً بشرياً

```sql
SELECT * FROM synced_entities WHERE sync_status = 'conflicted';
```

### سجلّ عمليات صفٍّ بعينه

```sql
SELECT operation, occurred_at, error_code, error_detail
FROM sync_operations_log
WHERE entity_name = 'notes' AND entity_id = '<id>'
ORDER BY occurred_at DESC;
```

يُقلَّم كل ٥٠ دورة (`SyncOperationsLog.trim`)، فالغياب من هنا لا يعني أن الحدث
لم يقع.

### الطابور الآن

```sql
SELECT job_id, entity_name, type, retry_count, max_retries, last_error
FROM sync_queue
ORDER BY priority, next_retry_at;
```

### قفلٌ عالق (تطوير فقط)

```dart
await getIt<SyncLock>().release();
```

`SyncLock` **داخليّ ولا يصدّره الباريل** — الوصول إليه هنا يفترض أنك داخل
الموديول أو تصحّح بجلسة تطوير. والإقلاع يحرّر القفل البائت وحده
(`releaseIfStale`، مهلة ١٠ دقائق)، فنداءٌ يدويّ نادراً ما يلزم.
